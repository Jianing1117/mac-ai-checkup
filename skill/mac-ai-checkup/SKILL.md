# AI 电脑体检

跟随用户的语言报告实测结果。默认只读盘点；用户已经批准的具体清理范围可直接执行，不重复索要相同授权。这个 skill 不自带定时任务，也不把安装或调用 skill 当作自动删除授权。

## 先查容易漏掉的地方

体检和清理时，先对照 `references/容易漏掉的地方.md`。那份清单里的东西不在"按大小找大文件"的结果里，也往往不报错：删了但还被程序占着的空间、App 内置浏览器的离线缓存、浏览器自己下载的本地模型、悄悄失败的后台服务和自动化、好几层"保持唤醒"、AI 自己留下的散乱文件和重复副本，以及删除时最容易出事的几种情况。报告里要单独说明这些查了没有。

## 先确定范围

此 skill 不依赖名为 AI Workspace 的文件夹，也不要求改变使用者现有的目录结构。把目录、应用和保护区当作本次任务的输入，通用流程留在本 skill 中。

按以下顺序确定工作目录：用户明确提供的路径；当前对话已确定的项目；用户选定的多个目录。自动生成的聊天目录不一定是用户想整理的工作区。没有明确范围时，先问一句“这次要整理哪个项目或文件夹？”，不要默认扫描主目录、整盘或所有云盘。

在内存中记录本次选定目录、操作系统、所用 AI 工具和用户指定的保护区即可，不默认写个人配置文件。只有用户要求记住设置时，才在其认可的位置保存本地配置；对外分享时排除该配置和实际盘点报告。

已有的 `work`、`tmp`、`outputs`、`deliverables` 等名称只是分类线索；结合项目约定确认用途。尚未确定用途的文件归为“待判断”，不为了统一结构批量迁移目录。

## 选择本次工作

- **体检与梳理**：检查选定目录、可再生成的缓存及技能目录，说明长期项目、成果、素材、过程文件和依赖的用途、容量与判断依据。
- **清理**：重新确认已授权的准确目标，按所属工具的正常清理方式执行，核对前后容量。
- **任务收尾**：只检查本次任务产生的文件、依赖和后台进程，说明成果、遗留物及处理建议。
- **整理 skills**：检查重复安装、功能重叠、实际使用证据和附带资源；先提出保留、停用或移除候选。

## 只读盘点

按本次范围选择脚本；路径相对于安装后的 skill 文件夹解析。不要为了运行脚本自动安装 Node.js，缺少运行环境时采用可用的只读文件工具。

通用目录盘点，适用于提供 Node.js 的环境，可重复传入多个目录：

```sh
node "<skill-folder>/scripts/workspace-audit.mjs" --workspace "<absolute-workspace-path>"
node "<skill-folder>/scripts/workspace-audit.mjs" --skills-root "<absolute-skills-directory>"
```

`workspace-audit.mjs` 使用 Node.js 内置功能，不依赖系统 shell 命令。它只统计选定目录的元数据；技能模式额外读取直接子目录中的 `SKILL.md`，用于比较主说明。支持 `--exclude "<absolute-protected-path>"` 排除保护区，`--max-entries` 和 `--max-depth` 限制扫描量。它拒绝主目录或磁盘根目录、跳过符号链接和常见敏感名称，输出扫描是否完整、排除项数量与逻辑文件大小。它不识别文件内容，不判断重复素材、项目是否闲置或删除是否安全。

macOS 系统缓存补充盘点：

```sh
node "<skill-folder>/scripts/audit.mjs"
```

`audit.mjs` 保留为 macOS 专用适配器，检查常见默认缓存、运行环境和独立技能目录；目录存在不代表应用当前正在使用它。自定义路径通过通用脚本显式传入。Windows、Linux 使用通用目录脚本；其系统缓存应根据所属工具的当前配置另行确认，不能照搬 macOS 路径或命令。

两种脚本都向标准输出返回 JSON，不生成报告、写日志、读取聊天内容或删除文件，也没有 `--apply` 模式。公开分享使用 skill 源文件，不附带用户的 JSON 盘点输出。

读取返回值中的 `status`、扫描完整性和限制；缺失、权限错误、排除项和被跳过的符号链接不代表零占用。通用脚本报告的逻辑大小不能冒充物理磁盘占用或实际释放量。脚本不会展开插件自带技能，也不会判定最后使用时间。报告必须注明覆盖范围。

如果需要检查项目依赖，仅在用户选定的工作目录内按目录元数据查找 `node_modules`、`.venv`、构建产物等，避免遍历整个主目录或跟随符号链接。容量和修改时间不能证明目录无用；有锁文件也不等于已验证可以恢复。

分清 RAM、磁盘缓存、运行环境、模型、聊天历史和用户成果。RAM 以当前内存压力为主要依据，不能把交换空间或缓存数字直接解释为故障。进程 RSS 可能重复计入共享内存。运行内存只做诊断与应用占用建议，不声称能通过删除磁盘缓存直接释放 RAM。

## 清理与验证

1. 记录准确路径、用途、清理前容量和磁盘可用空间。所有目标必须在本次授权内；拒绝宽泛根目录、凭据目录和意外符号链接。只读体检或“以后可以定期整理”的讨论不授权删除。
2. 下载缓存优先使用包管理器命令；先核对本机版本和命令作用范围。`npm cache clean` 与 npx 临时工具环境是不同对象，不能顺带清空后者。旧版 pip 可能未清理新版本的 `http-v2` 缓存，清后应实测。
3. Chrome、Brave 等浏览器优先使用应用的清理界面，选择用户授权的时间范围，仅选“缓存的图片和文件”。展开其他选项核对，保留 Cookies、历史、密码、自动填充、站点数据和权限。不要在浏览器运行时直接递归删除其配置目录。清理用标签页结束后关闭，保留原有标签页。
4. 模型、虚拟机、浏览器自动化二进制、常用依赖、聊天记录、项目成果及 skill 资产不按普通缓存处理。闲置项目要先确认用途、恢复方式及是否运行；只处理获批的派生文件。用户文件优先移到废纸篓，不清空其他废纸篓内容。
5. 再测目标目录容量和磁盘可用空间，报告“目标目录减少量”与“可用空间变化”。两者可能因缓存重建、快照或其他应用写入而不同。移到废纸篓只代表可恢复地移走，不等于释放空间。说明哪些缓存可重新下载、哪些移除可撤销。

如授权目标无法在不破坏正在使用的环境的情况下处理，先完成其他独立目标，准确说明剩余部分与原因，不扩大范围凑足某个 GB 数字。

## Skills 整理

- 区分独立技能、插件附带技能和系统内置技能。插件技能应通过所属插件管理，不直接删除插件缓存中的子目录。
- 相同名称不一定相同内容；`SKILL.md` 哈希相同也不能证明整个技能目录相同。处理重复前检查脚本、资产、软链接和其他客户端依赖。
- **没有可信使用记录就写“最后使用时间未知”**。访问或修改时间、描述在上下文出现、技能被扫描，都不能作为真实调用证据。不要为推测使用率全面读取私人聊天或含凭据的日志。
- 低频但重要的品牌、备份、发布、Vault 安全流程可以保留。优先处理用户确认停用的功能和已核实的重复安装。
- 停用适合验证是否影响工作；停用不释放磁盘空间。删除前给出具体技能、资产大小及恢复方式，取得对应授权。不要直接读取或展示可能含密钥的全局配置文件；优先使用应用提供的技能或插件管理入口。
- 月度只读复查、60–90 天无调用证据后再评估可作为建议，不作为默认自动删除规则。只有用户明确要求定期执行时才配置自动化，默认只通知有意义的新增候选或异常。

## 每个 AI 任务的收尾

遵循当前工作区的临时文件约定。普通问答默认留在聊天中；确需落盘时区分 `work` 过程文件与 `outputs` 最终成果，不擅自重排已有项目。

收尾报告只需说明：成果在哪里；本次新增的临时文件和依赖；本次启动且仍运行的服务；哪些已处理、哪些待确认。只停止能确认属于本次任务且已不需要的进程，不批量杀死所有 Node、Python 或浏览器进程。不把所有未跟踪文件视为本次生成物。

遵循用户指定的保护区、项目规则和凭据边界。不得为清理读取身份文件、密码、密钥或令牌。知识库、同步目录及备份目录按其既有规则处理；没有规则时先只读盘点。只有用户已有系统日志约定或明确要求时才草拟相应记录，按其授权范围写入。不要因一次体检新增报告文件、备份副本或永久后台服务；用户要求定期体检时，按下面「每周体检」执行。

## 每周体检（用户要求定期执行时）

这是可选模式：用户明确要求"每周体检"或类似的定期检查时才启用。它需要一份个人配置，放在用户认可的位置（默认 `~/.local/share/mac-ai-checkup/config.json`，在 skill 文件夹之外，分享时不带）。格式见 `config.example.json`。

**第一次设置**
1. 和用户确认要检查的地方：AI 工作区及其分层（在做 / 做完 / 过程）、AI 工具自动建的对话文件夹、仓库放哪、下载文件夹。按用户现有结构填，不为体检改结构。
2. 运行 `node "<skill-folder>/scripts/weekly-checkup.mjs" --current-baseline`，把当前后台状态（开机自启、常开端口、保持唤醒、自动化）逐项给用户过目，认可的才写进配置的 `baseline`。
3. 定时任务由用户在自己的 AI 工具里建；建之前先问。

**每次运行**

```sh
node "<skill-folder>/scripts/weekly-checkup.mjs" --save-state --out-dir "<报告文件夹>"
```

脚本只读，只列异常：过期的过程文件和成品、项目 `work/` 里的旧过程文件、很久没动的项目、AI 工具对话文件夹里的旧文件夹、主目录和桌面里散放的东西、下载里的旧大文件、没推送或重复的仓库、一周内暴涨的工具目录、删了但还被占着的空间、废纸篓里没清空的空间、App 内置浏览器攒下的离线缓存、浏览器自己下载的本地 AI 模型、特别大的日志、开机自启和后台服务的变化（包括悄悄失败的）、放在受保护文件夹里的后台程序、常开端口、长时间阻止睡眠的程序、自动化的增减，以及名字像凭证的文件（不打开）。`--save-state` 只保存磁盘和工具目录大小供下周对比；`--out-dir` 写一份报告，同名不覆盖。「这次没查成的」不等于没问题。

运行前，如果用户有一份记录系统现状的笔记，先读一遍：很多"异常"其实是用户早就决定过的，比如某个备份已经换了做法。

**用户回复要处理哪几项之后**
1. 动之前查引用。一个文件夹可能被这些地方按路径找：AI 工具的项目列表（Codex 在 `~/.codex/.codex-global-state.json`）、自动化和 skill 的配置（`~/.codex/automations`、`~/.codex/skills`、`~/.agents/skills`）、AI 记忆（`~/.claude/projects/*/memory`）、开机自启配置、`bin` 目录和 skills 目录里的软链接、工作区的 `AGENTS.md`/`CLAUDE.md`/`.claude/launch.json`、项目脚本里写死的绝对路径、正在运行的进程。被引用的先说清楚，不要直接移。
2. 移动或删除都先收进一个带日期的文件夹（如「第 N 轮 … MMDD」），再整个移进废纸篓；逐项记下从哪到哪。不清空废纸篓。
3. 挪了文件夹，就把写死的旧路径一起改掉，改完再查一遍引用。
4. 后台服务要用的程序，放在 `~/.local/share/` 这类不受保护的位置；放在文稿、桌面、下载里，后台服务读不到，会一直报错。
5. 名字像凭证的东西不打开、不复制，请用户自己挪进安全的地方。
6. 用户认可的新后台项目，加进配置的 `baseline`，并提议更新系统日志的「当前状态」。

**很久没动的项目，用户回「搬」「删」或「留」**
- 「搬」：先用几句话说清楚要做什么，等用户点头：建哪个私有仓库（默认私有）、从哪挪到哪、哪些地方会跟着改（AI 工具里的项目要重新添加、记忆和脚本里的路径）、有没有做好的 App 要装进「应用程序」。然后提交、推送（提交邮箱用 GitHub 提供的隐私邮箱，否则会被拒），核对本地和 GitHub 一致，再挪到仓库文件夹、改引用，最后报告改了哪些地方。项目推到主分支会自动上线的（比如网站），推之前单独再问。
- 「删」：同样先说清楚要删什么、有没有被引用，点头后收进带日期的文件夹再移进废纸篓。GitHub 网站上的仓库不动，除非用户另外说。
- 「留」：把项目名加进配置的 `workspace.keepProjects`，以后不再问。

## 交付与分享

一次整理交付：检查范围、带依据的候选、已执行的具体变更、前后测量和恢复方式。无法确认的项目保持“待判断”。需要分享此 skill 时，只包含通用说明、脚本和界面元数据；排除个人路径、真实目录清单、使用记录及运行日志。安装与平台边界见仓库的 `README.md`。
