# 你和 AI 都容易漏掉的地方

这些东西不在"按大小找大文件"的结果里，多数也不报错。清理和体检时逐条对照；报告里说明每一组查了没有、没查成的原因。

"这次的数字"来自作者自己的一台 MacBook（2026 年 9 月），只是举例，你的电脑会不一样。★ 是最值得先查的 12 条。

## 一、看不见的占用

| | 是什么 | 为什么会漏 | 怎么查 | 这次的数字 |
|---|---|---|---|---|
| ★ | 删了、但还被开着的程序占着的文件 | 文件夹里看不到，按大小找也找不到；常被误以为是"照片占的""系统数据" | `lsof -nP +L1`，同一个文件按"设备号 + 文件号"只算一次，排除 `/System`、`/usr`。退出占着的程序或重启电脑，空间才回来 | 重启一次多出 122 GB |
| ★ | App 内置浏览器的离线缓存 | 文件夹名叫 `Service Worker`，不叫 Cache；浏览器、飞书这类 Electron App 都有 | `find ~/Library/Application\ Support -maxdepth 8 -type d -name "Service Worker" -prune -exec du -sh {} +` | 飞书 17 GB 里 15 GB 是它 |
| ★ | 浏览器自己下载的本地 AI 模型 | 你没主动装过；网页版的 Gemini、ChatGPT 用不到它 | `du -sh ~/Library/Application\ Support/Google/Chrome/OptGuideOnDeviceModel` | Chrome 的 Gemini Nano 4 GB |
| ★ | 移进废纸篓的东西 | 以为"删了"就腾出来了 | `du -sh ~/.Trash`；访达设置里可以打开"30 天后移除废纸篓中的项目" | 攒到 160 GB |
| | 浏览器缓存到底是哪些网站的 | 笼统说"缓存"，不敢删 | `Service Worker/CacheStorage/<目录>/index.txt` 里有网址，按网站拆开看 | Brave 的 6.6 GB 里 6 GB 是飞书网页版 |
| | 剪辑软件的缓存 | 以为那是作品 | 剪辑软件设置里的缓存位置；和草稿分开看 | 剪映 12 GB 缓存，草稿只有 5.6 GB |
| | 项目里忘掉的依赖和虚拟环境 | 装一次就忘了，名字都叫 `node_modules`、`.venv` | 在工作区里按名字找，看所属项目还在不在做 | 一个 690 MB 的抠图环境 |
| | 工具卸载了，缓存还在 | 工具不在了，没人记得它的缓存 | `~/Library/Caches`、`~/.cache` 里对照已装的工具 | — |
| | AI 部署网站时反复下载的工具 | 每次都是"临时"下载 | `du -sh ~/.npm/_npx` | — |
| | 很久没重启 | 开机一两周，临时占用越积越多 | 报告里写上"距离上次重启多少天"（`sysctl kern.boottime`） | 见第一条 |

## 二、悄悄失败、悄悄耗电的后台

| | 是什么 | 为什么会漏 | 怎么查 | 这次的数字 |
|---|---|---|---|---|
| ★ | 后台服务读不到「文稿」「桌面」「下载」「iCloud 云盘」 | macOS 的隐私保护，不弹窗，只在日志里写 `Operation not permitted` | `launchctl print gui/$(id -u)/<名称>` 看 `last exit code`；日志里搜 `Operation not permitted`。后台要用的程序放到 `~/.local/share/` | 飞书机器人几个月不回消息，攒了 527 万行报错 |
| ★ | 自动化显示"启用中"，其实早就不产出了 | 只看状态，不看最后一次产出 | 看它最后一次写出东西是什么时候（输出文件的时间、运行记录） | 一个定时任务 13 周没产出；另一个显示"启用中"，一个半月没产出 |
| ★ | "保持唤醒"有好几层 | 关掉一个就以为好了；App 说"只在干活时"，实际不放 | `pmset -g assertions`（现在谁在挡）、`pmset -g log`（历史，重启不丢）、`pmset -g custom`（插电和电池的设置），再翻 App 自己的日志 | 一个 AI App 64 小时不让电脑睡 |
| ★ | 定时任务散在好几个地方 | 各家各管各的，一个地方查不到不等于没有 | `~/Library/LaunchAgents`、Codex 的 `~/.codex/automations/`、Claude Code 的定时任务、Claude App 的 Scheduled 页 | AI 说"你没有定时任务"，截图一看有两个 |
| | 忘了关的预览服务器 | AI 开完就走 | `lsof -nP -iTCP -sTCP:LISTEN`，看它在哪个文件夹里开的 | 开了 20 天 |
| | 同一件事有两套自动化 | 换了做法，旧的没删 | 系统定时任务和 AI 工具的自动化对照着看，确认真正在跑的是哪个 | 旧的备份任务一直失败，新的早就接手了 |
| | 自动化挂在一个对话上，对话的文件夹被清掉 | 那个文件夹看起来是空的、很久没动 | 定期任务用"每次新开"的独立任务；挂在对话上的只用来临时盯一件事 | 一个每天跑的看板差点断掉 |

## 三、AI 自己留下的乱

| | 是什么 | 为什么会漏 | 怎么查 | 这次的数字 |
|---|---|---|---|---|
| ★ | AI 随手建文件夹、随手放文件 | 每次都"放在当前文件夹就好" | 看工作区最上层有多少项；在 AI 的规矩里写清楚东西放哪（见 `templates/AGENTS.md`） | 最上层 78 项，看不出分组 |
| ★ | 同一个 skill 存了好几份 | 装过一次又复制过一次，改一份另一份不跟着变 | 对照 `~/.claude/skills`、`~/.codex/skills`、`~/.agents/skills` 里同名的；正本只留一处，别处放链接 | 3 份，AI 一直用的是旧版 |
| | 装了很多 skill，大多数没用过 | 装的时候觉得有用 | 看对话记录里真正调用过的次数；批量盘点时读到的不算 | 99 个里 65 个两个月没用过 |
| | 同一条规矩写在好几个文件里 | 每次加规矩都加在手边那份 | 全局一份，文件夹里只写这个文件夹自己的 | 9 个文件，同一条抄了五六遍 |
| | 同一个代码仓库有好几份 | 复制出来改，改完忘了 | 按 `git remote get-url origin` 分组 | 散在 5 处 |

## 四、删的时候最容易出事

| | 是什么 | 为什么会漏 | 怎么查 | 这次的例子 |
|---|---|---|---|---|
| ★ | "很久没改"不等于"没在用" | AI 按修改时间判断"旧" | 查正在运行的进程、开机自启、快捷方式指向它没有 | 121 天没动的文件夹，是机器人每天在跑的程序 |
| ★ | 引用不只写在文件内容里 | 搜文件内容搜不到快捷方式和 App 的设置 | 快捷方式（`find ~ -maxdepth 3 -type l` 再 `readlink`）、AI 工具的项目列表（Codex 在 `~/.codex/.codex-global-state.json`）、自动化、AI 的记忆、所有规则文件（`AGENTS.md` 和 `CLAUDE.md` 都要查） | 挪一个文件夹，要改 68 处路径 |
| ★ | "云端有备份"要拿记录核实 | 凭印象；还可能开着双向同步，本地一删云端也删 | 看网盘的上传、下载记录，逐个文件对大小；确认没开双向同步 | 逐个文件对过网盘记录才删 |
| | 清浏览器缓存会丢标签页 | 浏览器"启动时"没设成"继续浏览上次打开的网页" | 清之前先看这个设置，提醒用户 | — |
| | 覆盖文件前的比对没拦住 | 命令没等比对结果就接着覆盖了 | 比对不一致就停，别让后面的动作照常执行 | 一份副本被覆盖，靠前一天的备份找回 |
| | AI 也会说错 | 说得很确定 | 说"某个设置会删你的东西"之前，先查文档和实际文件 | 说 Claude 会删 30 天没动的会话，其实只删终端里开的 |
